# 원본 베이스라인 대비 현재 제출 코드 변경 사항

비교 대상은 저장소의 원본 `submit/script.py`와 2026-09-24에 만든 `submit.zip` 안의 `script.py`다. 아래의 “개선”은 **코드 동작의 변경**을 뜻한다. 새 코드의 F1 향상은 아직 GPU 추론으로 확인하지 않았다.

| 구분 | 원본 베이스라인 | 현재 제출 코드 | 노린 효과 |
|---|---|---|---|
| 공고·첨부 입력 | 문서 예산 기본 4,000자. 공고문을 먼저 넣고, 예산을 넘는 첨부는 통째로 제외 | 초기 상한 10,000자. 공고문·첨부에 예산을 배분하고, 긴 문서는 앞부분과 판정 관련 키워드가 있는 원문 행을 발췌 | 공고문 뒤쪽과 첨부에 있는 자격·금액·규격·일정 조건을 모델에 더 보여줌 |
| 문서 누락 표시 | 잘린 첫 문서와 제외된 후속 문서를 표시 | 발췌된 문서와 입력에 아예 제공되지 않은 문서를 구분하여 표시 | “보이지 않는다”와 “문서에 없다”를 혼동하지 않도록 도움 |
| 경쟁제품 지정표 | 공고의 품목코드를 제공 지정표와 대조해 모델에 제시하지 않음 | 세부품명번호를 지정표 CSV와 대조해 해당 품명·특이사항을 프롬프트에 추가 | 경쟁제품 해당 여부 및 지정 범위·예외를 코드 이름만으로 추측하지 않게 함 |
| 판정 지시 | 판단이 어려우면 0으로 내도록 지시 | 적용 조건과 제공 근거를 비교해 0/1을 판정하도록 지시. 추정가격 구간, 실제 참가 가능 기업 범위, 부재탐지, 공동수급 불허, 공급확약 제출 시점, SW 참여제한, 메타·문서 비교의 주의점을 추가 | 양성 누락과 적용 조건 혼동을 줄이려는 시도 |
| 명백한 비적용 예측 | 모델이 낸 양성 예측을 그대로 사용 | v17은 추정가격 1억원 이상, v13은 명시 품목이 지정표 밖, v21은 공동수급 불허인 경우에만 양성 예측을 0으로 교정 | 세 항목의 명백한 오탐을 제한적으로 제거 |
| 실행 보고 | 처리 건수·시간·JSON·근거 대조 결과 기록 | 기존 지표에 항목별 후처리 교정 건수를 추가 | GPU 실행 후 무엇이 바뀌었는지 확인 |

## 확인된 결과와 한계

- 로컬에서 현재 코드로 dev 200건을 **mock 실행**했고 CSV 형식 검사를 통과했다. mock은 모델 답을 전부 0으로 대체하므로 F1이나 GPU 실행시간 검증이 아니다.
- dev 정답의 비어 있지 않은 근거 문구 54개 중, **프롬프트를 구성하는 단계**에서 보이는 수는 원본 47개, 현재 54개였다. 이는 실제 vLLM 토큰 예산 조정 후에도 54개가 모두 남는다는 보장은 아니다.
- 기존 Runpod **원본 베이스라인 예측 파일**에 새 후처리 규칙만 적용하면 dev에서 오탐 54건(v13 31건, v17 5건, v21 18건)이 제거되고 정답 양성은 제거되지 않았다. 이때 24항목 양성 Macro F1은 0.185217에서 0.193467로 계산된다. **새 프롬프트로 다시 추론한 점수가 아니다.**
- 현재 제출 코드에는 법령 BM25, 임베딩 검색, `BAAI/bge-m3` 사용이 없다. 제공 법령의 관련 조항을 찾아 프롬프트에 넣는 단계도 없다.
- 24개 항목별 적용 조건·위반 조건·예외를 모두 체계화한 상태는 아니다. 따라서 이 변경만으로 목표 F1 0.90을 달성한다고 주장할 근거가 없다. 새 코드의 성능과 전체 1,853건 실행시간은 Runpod 또는 대회 서버에서 실제 실행해 확인해야 한다.
