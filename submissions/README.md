# 제출 코드 기록

제출할 때마다 이름이 다른 폴더에 ZIP 원본, ZIP에서 추출한 코드,
변경 이유, 파일별 SHA-256, 보관 시점의 Git 상태를 저장합니다.
기존 이름으로 다시 저장하면 실패하므로 과거 코드를 덮어쓰지 않습니다.
Git 상태는 보관 시점의 참고 정보이며 과거 ZIP의 제작 커밋을 의미하지 않습니다.

## 새 실험 제출본 만들기

프로젝트 루트에서 실행합니다. 이름은 영문·숫자·하이픈·밑줄을 사용합니다.

```sh
python3 tools/submissions.py save exp-001-longer-docs --note "공고 입력 길이를 늘려 문서 절단 영향을 비교"
```

`open/baseline/script.py`, `requirements.txt`(있는 경우), `model/`(있는 경우)을
보관합니다. 프롬프트와 기본 설정은 저장된 코드에 포함됩니다.
**출력된 `submissions/<이름>/submit.zip`을 직접 업로드하세요.**
루트의 `submit.zip`은 자동 갱신하지 않습니다. 이 도구를 사용하지 않고 ZIP을
만들거나 업로드하면 자동으로 기록되지 않습니다. 업로드 자체는 수동입니다.
저장 성공은 모델 실행·성능 검증 성공을 의미하지 않습니다.

## 점수 기록 및 조회

업로드한 버전의 이름에 실제 확인한 점수를 연결합니다. 다음 수치는 사용 예시입니다.

```sh
python3 tools/submissions.py result exp-001-longer-docs --kind public --score 0.21 --submission-id "제출번호" --note "제출 페이지에서 확인"
python3 tools/submissions.py list
```

dev 점수는 `--kind dev`로 구분합니다. 실행 옵션·평가 데이터·로그 위치는
`--note`에 함께 기록하세요. 결과를 추가해도 이전 결과는 유지됩니다.
잘못 입력한 점수는 새 결과에 정정 이유를 적어 추가하세요.
기존 ZIP은 `save <이름> --zip <파일> --note "설명"`으로 원본 그대로 보관합니다.
보관 폴더는 직접 수정하지 말고 Git이나 별도 백업으로 함께 보존하세요.

## 기존 기록의 해석

- `legacy-before-rag`: 기존 `submit_before_rag.zip` 원본. 실제 제출 여부·점수 미확인.
- `legacy-rag`: 기존 `submit.zip` 원본. 보관 당시 현재 코드와 바이트 일치.
- 사용자 보고 점수 **0.1979200359** (보고일 2026-09-16)는
  `open/baseline/script.py` 제출에 대한 값입니다. 실제 업로드 ZIP과의 연결은
  확인되지 않아 특정 버전의 점수로 등록하지 않았습니다.
- 보관 시간과 실제 제출 시간은 다릅니다. 기록 도구는 제출 사이트를 조회하지 않습니다.
